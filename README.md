# Учёт показателей НИР кафедры

Веб-приложение на Django для учёта показателей научно-исследовательской работы (НИР) кафедры вуза.

## Возможности

- вход в систему по логину и паролю, главная страница со сводкой по разделам;
- **Преподаватели** (`/teachers/`): профессорско-преподавательский состав кафедры. Хранятся ФИО, должность, учёная степень и звание, контакты, признак «работает на кафедре» и связь с учётной записью. Есть поиск по ФИО и фильтр по признаку работы. В карточке преподавателя собраны его НИОКР, публикации, РИД и доклады;
- **НИОКР** (`/research/`): название, период выполнения, статус, участники с ролями «руководитель» и «исполнитель». Есть поиск по названию и фильтр по статусу. В карточке НИОКР показаны её результаты: публикации и РИД;
- **Публикации** (`/publications/`): статьи, тезисы, монографии, главы, учебники и пособия. Хранятся выходные данные, DOI, индексирование (категория ВАК, РИНЦ, ядро РИНЦ, Scopus, Web of Science, квартиль), авторы в нужном порядке и связь с НИОКР. Фильтры: вид, год, индексирование;
- **РИД** (`/ip/`): патенты на изобретения, полезные модели, промышленные образцы, свидетельства на программы для ЭВМ и базы данных. Хранятся номер, даты заявки и регистрации, правообладатель, авторы, связь с НИОКР;
- **Конференции** (`/conferences/`): уровень (международная, всероссийская, региональная, вузовская), место и даты. На странице конференции — доклады с докладчиками и формой (пленарный, секционный, стендовый), к докладу можно привязать опубликованные тезисы;
- **Научные школы** (`/schools/`): научные направления кафедры, их ведущие учёные и защиты диссертаций. Главная страница раздела — сводная таблица показателей за последние 5 лет со строкой «Итого» и версией для печати;
- **Курсанты** (`/students/`): научная работа курсантов (студентов). Хранятся ФИО, учебная группа, курс, научный руководитель из преподавателей кафедры, статус (обучается, выпущен, отчислен) и персональные достижения: олимпиады, конкурсы, гранты, стипендии, выставки — с уровнем, результатом, датой и подтверждающим документом. В списке есть поиск по ФИО и группе, фильтры по курсу, группе, руководителю и статусу, число публикаций и достижений. В карточке курсанта — достижения по годам, публикации, доклады и РИД, сводка (публикации ВАК, РИНЦ, Scopus, WoS, достижения по уровням). В карточке преподавателя — блок «Научное руководство курсантами»;
- управление пользователями и всеми данными через админку Django (`/admin/`).

Авторами публикаций и РИД и докладчиками могут быть преподаватели кафедры и курсанты (выбираются из списков), а также внешние соавторы (ФИО вписывается текстом).

**Публикации курсантов** отдельно не ведутся: это обычные записи раздела «Публикации», где курсант указан одним из авторов. Статья курсанта с руководителем хранится один раз и видна в карточках обоих. Отчисленные курсанты не предлагаются в новых записях, но остаются в уже сохранённых.

Регистрации через сайт нет: пользователей заводит администратор.

Другие разделы (финансирование НИОКР, аспиранты и т.п.) будут добавлены позже. Учётных записей для курсантов нет: их данные ведут редакторы и научные руководители.

## Показатели научных школ

Показатели не вводятся вручную, а считаются автоматически при каждом открытии страницы.

- **Период** — текущий календарный год и четыре предыдущих (в 2026 году: 2022–2026). Задаётся в `apps/schools/period.py`.
- **Принадлежность к школе** задаётся явно: в карточке публикации или РИД отмечаются научные школы. По авторам принадлежность не определяется, ведь учёный может публиковаться и вне своего направления.
- **Защищено диссертаций** — защиты школы с датой защиты в периоде, отдельно кандидатские и докторские. Защиты ведутся в карточке школы.
- **Монографии** и **главы в монографиях** — публикации соответствующего вида с годом в периоде, считаются раздельно.
- **Публикации ВАК** — публикации с заполненной категорией ВАК (К1–К3) с годом в периоде. Статьи только в Scopus или WoS без категории ВАК не учитываются.
- **РИД** — РИД с датой регистрации в периоде.
- **Итого** — число уникальных записей: публикация, отнесённая к двум школам, в итоге учитывается один раз.

Правила подсчёта собраны в `apps/schools/indicators.py`.

Научную школу, к которой относятся защиты, удалить нельзя: сначала нужно удалить или перенести защиты. Если школа больше не работает, снимите отметку «действующая». Связи с публикациями и РИД при удалении школы снимаются, сами записи остаются.

## Права доступа

| Кто | Что может |
|---|---|
| Любой вошедший пользователь | просматривать все разделы |
| Группа **«Преподаватели»** | просматривать научные школы и курсантов; добавлять публикации, РИД, доклады и конференции (в том числе с курсантами-соавторами) и относить свои публикации и РИД к научным школам; изменять и удалять **только свои** публикации, РИД и доклады — те, где он сам указан автором или докладчиком; изменять карточки **своих подопечных** курсантов (где он научный руководитель) и вести их достижения. Добавлять и удалять курсантов не может |
| Группа **«Редакторы НИР»** со «Статусом персонала» | добавлять, изменять и удалять любые записи на сайте и в админке |
| Суперпользователь | всё, включая управление пользователями |

Обе группы создаются миграциями. Пользователя добавляет в группу администратор: `/admin/` → Пользователи → пользователь → поле «Группы».

**Как подключить преподавателя:**
1. Создайте ему учётную запись (`/admin/` → Пользователи → «Добавить»).
2. Добавьте пользователя в группу «Преподаватели». «Статус персонала» не ставьте.
3. В карточке преподавателя (`/teachers/` → преподаватель → «Изменить») выберите эту учётную запись в поле «Учётная запись».

Без шага 3 система не знает, какие записи «его», и преподаватель может только просматривать. При добавлении записи он автоматически подставляется первым автором. Убрать себя из авторов нельзя, иначе он потерял бы доступ к записи. Конференцию преподаватель может добавить, чтобы указать в ней свой доклад, а изменять конференции могут только редакторы.

Преподавателя, который участвует в НИОКР, публикациях, РИД или докладах либо руководит курсантами, удалить нельзя: вместо этого снимите отметку «работает на кафедре». Так сохраняется история участия.

Курсанта, который указан автором публикаций, РИД или докладов, тоже удалить нельзя: сначала уберите его из авторов или измените статус на «выпущен» либо «отчислен». Достижения курсанта удаляются вместе с ним.

## Быстрый старт (разработка)

Нужен [uv](https://docs.astral.sh/uv/). Python 3.12+ он установит сам.

```bash
uv venv --python 3.12
uv pip sync requirements.txt

cp .env.example .env              # затем задайте DJANGO_SECRET_KEY и DJANGO_DEBUG=True
uv run python manage.py migrate
uv run python manage.py create_admin     # создаёт admin / 123
uv run python manage.py runserver
```

Откройте http://127.0.0.1:8000/ и войдите как `admin` / `123`.

> **Внимание:** `admin` / `123` подходят только для разработки. Перед вводом в эксплуатацию смените пароль (см. [DEPLOY.md](DEPLOY.md)).

Запуск тестов:

```bash
uv run python manage.py test
```

## Демонстрационные данные

> Команды ниже — **только для разработки и демонстрации**. Они меняют данные в текущей базе (из `.env`). При `DJANGO_DEBUG=False` они без параметра `--force` не запускаются.

Заполнить базу демонстрационными данными: преподаватели, НИОКР, публикации, РИД, конференции, научные школы и защиты, курсанты с достижениями (курсанты — соавторы части публикаций, докладов и РИД). Даты привязаны к текущему отчётному периоду, часть записей специально раньше периода.

```bash
uv run python manage.py seed_demo            # если в базе уже есть данные, команда остановится
uv run python manage.py seed_demo --clear    # сначала очистить базу (admin сохранится)
uv run python manage.py seed_demo --seed 42  # другой набор данных; одинаковое зерно — одинаковые данные
```

Создаются демо-пользователи, пароль у всех — `demo12345`:

| Логин | Роль |
|---|---|
| `editor` | редактор (группа «Редакторы НИР») |
| `ivanov`, `petrova`, `smirnov` | преподаватели (группа «Преподаватели»), привязаны к своим карточкам; у `ivanov` есть подопечные курсанты |

Очистить базу: удалить все предметные данные и всех пользователей, кроме `admin`. Группы и права сохраняются.

```bash
uv run python manage.py clear_data                   # покажет, что будет удалено, и спросит подтверждение
uv run python manage.py clear_data --noinput         # без вопроса
uv run python manage.py clear_data --username boss   # сохранить другого пользователя вместо admin
```

Если сохраняемого пользователя нет в базе, `clear_data` ничего не удаляет.

Развёртывание на сервере описано в [DEPLOY.md](DEPLOY.md).

## Структура проекта

```
.
├── apps/
│   ├── accounts/                 # пользователи: модель User (AbstractUser), админка
│   │   └── management/commands/
│   │       └── create_admin.py   # создание/сброс суперпользователя
│   ├── core/                     # главная страница, общие формы, поиск, права (permissions.py), группа «Преподаватели»
│   ├── staff/                    # преподаватели: Teacher, общая модель автора AuthorBase, /teachers/
│   ├── research/                 # НИОКР: модели ResearchProject и Participant, страницы /research/
│   ├── publications/             # публикации: Publication, PublicationAuthor, страницы /publications/
│   ├── ip/                       # РИД: IntellectualProperty, IntellectualPropertyAuthor, страницы /ip/
│   ├── conferences/              # конференции и доклады: Conference, Report, ReportSpeaker, /conferences/
│   ├── schools/                  # научные школы и защиты: ScientificSchool, DissertationDefense, показатели, /schools/
│   └── students/                 # НИР курсантов: Student, StudentAchievement, /students/
├── config/                       # настройки проекта (settings, urls, wsgi)
├── templates/
│   ├── base.html                 # базовый шаблон с шапкой
│   ├── registration/login.html   # страница входа
│   ├── core/home.html            # главная страница
│   ├── staff/                    # шаблоны раздела «Преподаватели»
│   ├── research/, publications/, ip/, conferences/, schools/, students/   # шаблоны разделов
│   └── includes/                 # общие фрагменты: постраничный вывод, поле формы, авторы, удаление
├── static/vendor/bootstrap/      # Bootstrap 5 (локальная копия)
├── .env.example                  # пример переменных окружения
├── requirements.txt
├── DEPLOY.md                     # инструкция по развёртыванию
└── manage.py
```

Новые предметные модули добавляйте как отдельные приложения в `apps/`:

```bash
mkdir apps/<имя> && uv run python manage.py startapp <имя> apps/<имя>
```

Затем в `apps/<имя>/apps.py` укажите `name = 'apps.<имя>'` и добавьте `'apps.<имя>'` в `INSTALLED_APPS`.
