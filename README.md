# Учёт показателей НИР кафедры

Веб-приложение на Django для учёта показателей научно-исследовательской работы (НИР) кафедры вуза.

## Возможности

- вход в систему по логину и паролю, главная страница со сводкой по разделам;
- **Преподаватели** (`/teachers/`): профессорско-преподавательский состав кафедры. Хранятся ФИО, должность, учёная степень и звание, контакты, признак «работает на кафедре» и связь с учётной записью. Есть поиск по ФИО и фильтр по признаку работы. В карточке преподавателя собраны его НИОКР, публикации, РИД и доклады;
- **НИОКР** (`/research/`): название, период выполнения, статус, участники с ролями «руководитель» и «исполнитель». Есть поиск по названию и фильтр по статусу. В карточке НИОКР показаны её результаты: публикации и РИД;
- **Публикации** (`/publications/`): статьи, тезисы, монографии, главы, учебники и пособия. Хранятся выходные данные, форма работы (печатная или электронная), объём в печатных листах, DOI, индексирование (категория ВАК, РИНЦ, ядро РИНЦ, Scopus, Web of Science, квартиль), авторы в нужном порядке и связь с НИОКР. Фильтры: вид, год, индексирование;
- **РИД** (`/ip/`): патенты на изобретения, полезные модели, промышленные образцы, свидетельства на программы для ЭВМ и базы данных. Хранятся номер, даты заявки и регистрации, правообладатель, авторы, связь с НИОКР;
- **Конференции** (`/conferences/`): уровень (международная, всероссийская, региональная, вузовская), место и даты. На странице конференции — доклады с докладчиками и формой (пленарный, секционный, стендовый), к докладу можно привязать опубликованные тезисы;
- **Научные школы** (`/schools/`): научные направления кафедры, их ведущие учёные и защиты диссертаций. Главная страница раздела — сводная таблица показателей за последние 5 лет со строкой «Итого» и версией для печати;
- **Курсанты** (`/students/`): научная работа курсантов (студентов). Хранятся ФИО, учебная группа, курс, научный руководитель из преподавателей кафедры, статус (обучается, выпущен, отчислен) и персональные достижения: олимпиады, конкурсы, гранты, стипендии, выставки — с уровнем, результатом, датой и подтверждающим документом. В списке есть поиск по ФИО и группе, фильтры по курсу, группе, руководителю и статусу, число публикаций и достижений. В карточке курсанта — достижения по годам, публикации, доклады и РИД, сводка (публикации ВАК, РИНЦ, Scopus, WoS, достижения по уровням), задачи от научного руководителя. В карточке преподавателя — блок «Научное руководство курсантами». Курсант с учётной записью ведёт **личный кабинет** (см. «Личный кабинет»);
- **Адъюнктура** (`/adjuncts/`): адъюнкты (аспиранты) кафедры — тема диссертации, научная специальность, год поступления, форма и срок обучения, научный руководитель, научная школа, статус (обучается, академический отпуск, окончил, защитился, отчислен), планируемый год защиты. В карточке адъюнкта — индивидуальный план работы по годам обучения с процентом выполнения, задачи, достижения, публикации, доклады и РИД со сводкой. Адъюнкт входит в систему под своей учётной записью;
- **Менеджер задач** (`/tasks/` — «Мои задачи»): научный руководитель ставит задачи адъюнкту (срок, приоритет, связь с этапом плана) и курсанту. Исполнитель с учётной записью сам двигает задачу к проверке, обе стороны обсуждают её в комментариях; задачу курсанта без учётной записи руководитель ведёт сам. Просроченные задачи выделены, в шапке показано число задач, ждущих внимания;
- **Отчёты** (`/reports/`): отчётные документы по данным системы — список трудов по форме № 16 и отчёт об активности пользователей (страница, печать, DOCX);
- **Журнал активности**: входы, просмотры страниц, изменения данных и выгрузки отчётов пишутся автоматически;
- **Личный кабинет** преподавателя, адъюнкта и курсанта: каждый видит только свои записи, своих подопечных и свои задачи; все данные кафедры — у редакторов;
- управление пользователями и всеми данными через админку Django (`/admin/`).

Авторами публикаций и РИД и докладчиками могут быть преподаватели кафедры, курсанты и адъюнкты (выбираются из списков), а также внешние соавторы (ФИО вписывается текстом).

**Публикации курсантов и адъюнктов** отдельно не ведутся: это обычные записи раздела «Публикации», где курсант или адъюнкт указан одним из авторов. Статья с руководителем хранится один раз и видна в карточках обоих. Отчисленные курсанты и адъюнкты не предлагаются в новых записях, но остаются в уже сохранённых.

Регистрации через сайт нет: пользователей заводит администратор.

Другие разделы (например, финансирование НИОКР) будут добавлены позже. Учётная запись курсанту необязательна: без неё его данные ведут редакторы и научный руководитель.

## Адъюнктура

- **Курс** не хранится, а вычисляется по году поступления: учебный год начинается 1 сентября (в октябре 2026 года поступивший в 2025 году учится на 2 курсе). Для статусов «окончил», «защитился» и «отчислен» курс не показывается. Если курс больше нормативного срока, выводится пометка «срок обучения истёк». Расчёт — в `apps/adjuncts/study.py`.
- **Индивидуальный план** — этапы подготовки диссертации по годам обучения (кандидатские экзамены, публикации, главы, апробация, предзащита) с плановым сроком, статусом и отметкой руководителя. План ведут руководитель и редакторы, адъюнкт может отметить запланированный этап как «выполняется».
- **Задачи** — оперативные поручения руководителя. Их видят **только** сам адъюнкт, его научный руководитель и редакторы; для остальных страницы задач не существуют (404). Статусы: «новая» → «в работе» → «на проверке» → «выполнена» (или «отменена»).
  - Руководитель и редактор создают, изменяют и удаляют задачи и переводят их в любой статус. «Выполнена» ставит только руководитель (редактор) — это приёмка; дата завершения заполняется автоматически.
  - Адъюнкт двигает задачу по цепочке «новая → в работе → на проверке» и может вернуть её с проверки в работу.
  - Каждая смена статуса автоматически добавляет в обсуждение служебную запись. Комментировать могут все, кто видит задачу; свой комментарий можно удалить в течение 15 минут.
  - В шапке рядом с «Мои задачи» — число задач, ждущих внимания: у адъюнкта и курсанта — новые, у руководителя — задачи на проверке плюс просроченные открытые задачи курсантов без учётной записи (подсказка при наведении на число).
- **Задачи курсантов** работают в том же менеджере задач (одна модель `Task`: исполнитель — адъюнкт или курсант):
  - задачи курсанта видят **только** он сам (если у него есть учётная запись), его научный руководитель и редакторы; для остальных, в том числе адъюнктов и других преподавателей, — 404. Создают, изменяют и удаляют их руководитель и редакторы. У курсанта без руководителя задачи ведут только редакторы; при смене руководителя задачи видны новому руководителю;
  - курсант с учётной записью работает с задачами как адъюнкт (цепочка «новая → в работе → на проверке», «выполнена» ставит руководитель). У курсанта без учётной записи задачу целиком ведёт руководитель, и статусы — «новая», «в работе», «выполнена», «отменена»: «на проверке» не используется;
  - страницы: `/students/<id>/tasks/` (список с фильтром по статусу) и `/students/<id>/tasks/add/`; в карточке курсанта — открытые задачи, в списке курсантов и в карточке руководителя — число открытых задач;
  - в «Моих задачах» руководителя — задачи и адъюнктов, и курсантов, с фильтром «Исполнитель».
- Правила доступа к задачам собраны в `apps/adjuncts/access.py`.

## Личный кабинет

Преподаватель, адъюнкт и курсант с привязанной учётной записью видят в системе **только то, что касается их самих**. Главная страница для каждого из них — его карточка, она же личный кабинет. Общие списки разделов, чужие карточки и записи, сводные показатели и админка им закрыты: страница вне белого списка роли отвечает 403, чужая запись — 404. Полный доступ ко всем данным — у редакторов (группа «Редакторы НИР» со «Статусом персонала») и суперпользователя.

**Преподаватель** (кабинет — `/teachers/<свой id>/`, кнопки «Добавить публикацию», «Добавить РИД», «Добавить доклад», число задач, ждущих внимания). В шапке — «Мой кабинет», «Мои подопечные», «Мои задачи». Открыто:
- свои публикации, РИД и доклады (добавление, изменение, удаление — по правам ниже), конференции со своим докладом, добавление конференции и выбор конференции для доклада (`/conferences/reports/add/`);
- НИОКР, где он участник, — просмотр;
- научные школы, где он ведущий учёный, — страница школы с её показателями;
- подопечные курсанты и адъюнкты: их карточки и всё, что руководителю разрешено (карточка, достижения, план адъюнкта, задачи); их публикации, доклады и РИД — просмотр;
- «Мои задачи», задачи подопечных.

**Адъюнкт** (кабинет — `/adjuncts/<свой id>/`: сведения, план работы, задачи, достижения, труды; кнопки «Добавить публикацию», «Добавить РИД», «Добавить доклад», «Добавить достижение»). В шапке — «Мой кабинет», «Мои задачи». Открыто: своя карточка и изменение контактов, отметка этапа плана «выполняется», свои задачи и достижения, свои публикации, РИД и доклады, конференции со своим докладом, своя научная школа (просмотр). Карточка научного руководителя закрыта — его ФИО показывается текстом.

**Курсант** (кабинет — `/students/<свой id>/`: сведения, сводка, задачи, публикации, доклады, РИД, достижения; кнопки «Добавить публикацию», «Добавить доклад», «Добавить достижение»). В шапке — «Мой кабинет», «Мои задачи». Открыто: своя карточка, свои задачи (смена статуса по цепочке, комментарии), свои публикации и доклады (добавление, изменение, удаление), конференции со своим докладом, РИД, где он соавтор, — только просмотр, свои достижения.

В выпадающих списках форм видны все люди кафедры, конференции, НИОКР и научные школы — они нужны, чтобы указать соавторов, мероприятие, проект и школу. В выборе публикации для доклада — только свои публикации. На открытых страницах ссылки на закрытые карточки и записи показываются текстом. Портфолио не дублируется: это обычные записи разделов, где человек указан автором.

Ограничение действует в одном месте — `apps/core/cabinet.py` (`CabinetMiddleware`): белые списки ролей — `RULES` (имя URL → проверка «запись своя»). Новая страница, не добавленная в список роли, закрыта автоматически. Ссылки в шаблонах выводятся тегом `{% record_link %}` и фильтром `openable` (`apps/core/templatetags/cabinet.py`), которые спрашивают тот же механизм. Механизм ограничивает только видимость: права на действия задаются группами и `apps/core/permissions.py`.

Пользователь без привязанной карточки (не редактор) видит все разделы только для просмотра, как раньше.

## Отчёты

Раздел `/reports/` — отчётные документы, которые система формирует по уже введённым данным (отдельных таблиц для отчётов нет). Список отчётов на странице раздела зависит от пользователя.

### Форма № 16 — список научных и учебно-методических трудов

- **Кому доступна:** преподаватель, адъюнкт и курсант с учётной записью — на себя (`/reports/form16/`, кнопка «Форма 16» в кабинете); научный руководитель — также на своих подопечных курсантов и адъюнктов (кнопка в их карточках); редактор — на любого человека кафедры (выбор в форме). Чужой отчёт для остальных — 404. Адрес отчёта на человека — `/reports/form16/<teacher|adjunct|student>/<id>/`: вид нужен, потому что номера у преподавателя, адъюнкта и курсанта могут совпадать.
- **Параметры:** период (год с — по, по умолчанию все годы) и разделы.
- **Разделы** (нумерация сквозная): 1) научные труды — статьи, тезисы, монографии, главы; 2) учебные и учебно-методические издания — учебники и учебные пособия; 3) объекты интеллектуальной собственности — патенты и свидетельства (РИД). Внутри раздела — по году, затем по названию, от ранних к поздним.
- **Столбцы:** № п/п; наименование и вид («Название (статья)»); форма работы — из поля публикации, для РИД: программы и базы данных — электронная, патенты — печатная; выходные данные — выходные данные публикации и DOI, для РИД — номер, дата регистрации, правообладатель; объём — поле «объём, п. л.», а если оно пустое — число страниц из диапазона («15–28» → «14 с.») или текст поля «страницы»; соавторы — все авторы, кроме самого человека, в порядке авторов, внешние — как записаны.
- **Доклады** входят своими опубликованными тезисами (доклад, связанный с публикацией). Доклады без опубликованных тезисов в форму не включаются: в форму 16 вносят опубликованные труды.
- **Заголовок:** «Автор: Фамилия Имя Отчество» (без склонения ФИО — для этого понадобилась бы морфологическая библиотека), должность и степень или категория («адъюнкт…», «курсант, учебная группа…»), период. В конце — строки для подписей автора, заведующего кафедрой и учёного секретаря и дата формирования.
- **Выгрузка:** кнопка «Скачать DOCX» (A4, Times New Roman 12 пт, заголовок таблицы повторяется на каждой странице; имя файла вида `Форма_16_Иванов_С_П.docx`) и «Версия для печати» (печать страницы браузером без меню и кнопок).

Данные отчёта собираются в `apps/reports/form16.py` (`build_form16`); страница и DOCX (`apps/reports/docx_export.py`, библиотека python-docx) строятся из одного результата.

### Активность пользователей

- **Кому доступен:** суперпользователю и тем, кому вручную выдано право «Может смотреть отчёт об активности пользователей» (`/admin/` → Пользователи → пользователь → «Права пользователя», `activity | … | view_activity_report`). Редакторам по умолчанию недоступен: журнал содержит персональные данные. Остальным — 403.
- **Параметры:** период «с — по» с датой и временем (по умолчанию последние 7 суток), категории пользователей, флажок «Показывать пользователей без активности».
- **Таблица** (`/reports/activity/`): блоки по категориям — администраторы (суперпользователи), редакторы (`is_staff`), преподаватели, адъюнкты, курсанты, прочие пользователи; у каждого пользователя ровно одна категория, по этому приоритету. Отдельный блок — неудачные входы с несуществующими логинами и действия удалённых пользователей (по введённому имени). Столбцы: входов, неудачных входов, просмотров страниц, добавлено, изменено, удалено, выгрузок отчётов, первая и последняя активность; итоги по категориям и общий итог. Внутри категории — сначала недавно активные.
- **Подробный журнал:** логин в таблице ведёт на `/reports/activity/user/<id>/` (или `/reports/activity/name/<логин>/` для записей без пользователя) — хронология за тот же период с фильтром по действию.
- **Выгрузка:** «Скачать DOCX» — та же таблица с теми же параметрами (A4 альбомная, Times New Roman, заголовок таблицы повторяется на каждой странице), имя файла вида `Активность_пользователей_21.10.2026-28.10.2026.docx`.

Данные собираются в `apps/reports/activity.py` агрегирующими запросами (число запросов не зависит от числа пользователей), DOCX — `apps/reports/activity_docx.py`. Общее оформление DOCX обоих отчётов — `apps/reports/docx_common.py`.

### Как добавить отчёт

1. Модуль с построением данных в `apps/reports/` (по образцу `form16.py`).
2. Представление и адрес в `apps/reports/views.py` и `urls.py`.
3. Запись `ReportType` в `REPORTS` (`apps/reports/registry.py`): название, описание, адрес и кому доступен.
4. Если отчёт нужен преподавателям, адъюнктам или курсантам — его страницы в белые списки `RULES` (`apps/core/cabinet.py`), иначе им он будет закрыт.

## Журнал активности

Журнал (`apps/activity`, модель `ActivityLog`) пишется автоматически, без вызовов в представлениях:
- **вход, выход, неудачный вход** — сигналы Django; при неудачном входе сохраняется введённый логин (пароль — никогда);
- **просмотр страницы** — успешный (код 200) GET-запрос вошедшего пользователя к HTML-странице; статика, медиа, админка, ошибки и анонимные запросы не пишутся (`ActivityMiddleware`);
- **выгрузка отчёта** — скачивание файла (DOCX);
- **добавление, изменение, удаление** главных записей — преподаватели, НИОКР, публикации, РИД, конференции, доклады, научные школы, защиты, курсанты и их достижения, адъюнкты, этапы плана, достижения адъюнктов, задачи и комментарии (список — `TRACKED_MODELS` в `apps/activity/signals.py`); строки авторов и участников отдельно не пишутся. Изменения через админку тоже попадают в журнал.

Сохраняются пользователь и его логин, время, действие, объект (тип, номер, краткое название), адрес страницы и IP. Содержимое форм и значения полей не сохраняются. Изменения без пользователя (`seed_demo`, `clear_data`, миграции, `shell`) не пишутся. Сбой записи в журнал не мешает работе пользователя — ошибка уходит в лог приложения.

- **Срок хранения** — `ACTIVITY_LOG_DAYS` в `.env` (по умолчанию 365 дней); старые записи удаляет `uv run python manage.py purge_activity_log` (параметр `--days` — другой срок). На сервере команду запускают раз в сутки (DEPLOY.md, раздел 3.8).
- **IP за прокси:** по умолчанию берётся адрес соединения (`REMOTE_ADDR`). За Nginx он всегда `127.0.0.1`, поэтому там включают `ACTIVITY_TRUST_PROXY_HEADER=True` — тогда адрес берётся из заголовка `X-Real-IP`, который выставляет Nginx. Без прокси эту настройку не включайте: заголовок может подделать любой клиент.
- **Просмотр:** отчёт «Активность пользователей» и админка (`/admin/` → Журнал активности; только просмотр, удаление — суперпользователю).
- `clear_data` очищает журнал вместе с данными; `seed_demo` создаёт демонстрационный журнал за 30 дней.

## Показатели научных школ

Показатели не вводятся вручную, а считаются автоматически при каждом открытии страницы.

- **Период** — текущий календарный год и четыре предыдущих (в 2026 году: 2022–2026). Задаётся в `apps/schools/period.py`.
- **Принадлежность к школе** задаётся явно: в карточке публикации или РИД отмечаются научные школы. По авторам принадлежность не определяется, ведь учёный может публиковаться и вне своего направления.
- **Защищено диссертаций** — защиты школы с датой защиты в периоде, отдельно кандидатские и докторские. Защиты ведутся в карточке школы.
- **Монографии** и **главы в монографиях** — публикации соответствующего вида с годом в периоде, считаются раздельно.
- **Публикации ВАК** — публикации с заполненной категорией ВАК (К1–К3) с годом в периоде. Статьи только в Scopus или WoS без категории ВАК не учитываются.
- **РИД** — РИД с датой регистрации в периоде.
- **Итого** — число уникальных записей: публикация, отнесённая к двум школам, в итоге учитывается один раз.

Правила подсчёта собраны в `apps/schools/indicators.py`.

Научную школу, к которой относятся защиты, удалить нельзя: сначала нужно удалить или перенести защиты. Если школа больше не работает, снимите отметку «действующая». Связи с публикациями и РИД при удалении школы снимаются, сами записи остаются.

## Права доступа

| Кто | Что может |
|---|---|
| Вошедший пользователь без карточки человека и без групп | просматривать все разделы |
| Группа **«Преподаватели»** | видеть только свой кабинет (см. «Личный кабинет»): свои записи, своих подопечных, свои НИОКР и школы; добавлять публикации, РИД, доклады и конференции (в том числе с курсантами-соавторами) и относить свои публикации и РИД к научным школам; изменять и удалять **только свои** публикации, РИД и доклады — те, где он сам указан автором или докладчиком; изменять карточки **своих подопечных** курсантов и адъюнктов (где он научный руководитель), вести их достижения, план работы адъюнкта и задачи адъюнктов и курсантов. Добавлять и удалять курсантов и адъюнктов не может |
| Группа **«Адъюнкты»** | видеть только свой кабинет; то же, что у преподавателя, для своих трудов: добавлять публикации, РИД, доклады и конференции, изменять и удалять **только свои** (где он указан автором или докладчиком); вести свои достижения; изменять в своей карточке контакты; видеть свой план и отмечать этапы как «выполняется»; работать со своими задачами по правилам выше |
| Группа **«Курсанты»** | только личный кабинет (см. «Личный кабинет»): добавлять, изменять и удалять **свои** публикации, доклады и достижения, добавлять конференции для своих докладов, просматривать свои РИД, работать со своими задачами. Чужие данные не видит |
| Группа **«Редакторы НИР»** со «Статусом персонала» | видеть все разделы и сводные показатели; добавлять, изменять и удалять любые записи на сайте и в админке |
| Суперпользователь | всё, включая управление пользователями, журнал и отчёт об активности |
| Право «Может смотреть отчёт об активности пользователей» (выдаётся вручную) | отчёт об активности пользователей и подробные журналы |

Все группы создаются миграциями. Пользователя добавляет в группу администратор: `/admin/` → Пользователи → пользователь → поле «Группы».

**Как подключить преподавателя:**
1. Создайте ему учётную запись (`/admin/` → Пользователи → «Добавить»).
2. Добавьте пользователя в группу «Преподаватели». «Статус персонала» не ставьте.
3. В карточке преподавателя (`/teachers/` → преподаватель → «Изменить») выберите эту учётную запись в поле «Учётная запись».

**Как подключить адъюнкта** — так же: учётная запись → группа «Адъюнкты» (без «Статуса персонала») → в карточке адъюнкта (`/adjuncts/` → адъюнкт → «Изменить», это может сделать редактор) поле «Учётная запись». Одна учётная запись не может быть привязана одновременно к двум людям (преподавателю, адъюнкту, курсанту).

**Как подключить курсанта:**
1. Администратор создаёт учётную запись (`/admin/` → Пользователи → «Добавить»), «Статус персонала» не ставит.
2. Добавляет её в группу «Курсанты».
3. Привязывает к карточке курсанта: `/admin/` → Курсанты → курсант → поле «Учётная запись» (в списке курсантов в админке есть фильтр «Учётная запись: пусто / не пусто»).

Без шага 3 система не знает, какие записи «его», и преподаватель (адъюнкт) может только просматривать. При добавлении записи он автоматически подставляется первым автором. Убрать себя из авторов нельзя, иначе он потерял бы доступ к записи. Конференцию преподаватель может добавить, чтобы указать в ней свой доклад, а изменять конференции могут только редакторы.

Преподавателя, который участвует в НИОКР, публикациях, РИД или докладах либо руководит курсантами или адъюнктами, удалить нельзя: вместо этого снимите отметку «работает на кафедре». Так сохраняется история участия.

Курсанта, который указан автором публикаций, РИД или докладов, тоже удалить нельзя: сначала уберите его из авторов или измените статус на «выпущен» либо «отчислен». Достижения и задачи курсанта удаляются вместе с ним. Так же с адъюнктом: нельзя удалить того, кто указан автором или связан с защитой диссертации; план, задачи и достижения удаляются вместе с ним.

## Быстрый старт (разработка)

Нужен [uv](https://docs.astral.sh/uv/). Python 3.12+ он установит сам.

```bash
uv venv --python 3.12
uv pip sync requirements.txt

cp .env.example .env              # затем задайте DJANGO_SECRET_KEY и DJANGO_DEBUG=True
uv run python manage.py migrate
uv run python manage.py create_admin     # создаёт admin / 123
uv run python manage.py seed_demo        # необязательно: демонстрационные данные и пользователи
uv run python manage.py runserver
```

Откройте http://127.0.0.1:8000/ и войдите как `admin` / `123`.

> **Внимание:** `admin` / `123` подходят только для разработки. Перед вводом в эксплуатацию смените пароль (см. [DEPLOY.md](DEPLOY.md)).

Запуск тестов:

```bash
uv run python manage.py test
```

## Демонстрационные данные

> Команды ниже — **только для разработки и демонстрации**. Они меняют данные в текущей базе (из `.env`). При `DJANGO_DEBUG=False` они без параметра `--force` не запускаются.

Команда `seed_demo` заполняет базу данными всех разделов:
- преподаватели, НИОКР, публикации, РИД, конференции с докладами, научные школы и защиты диссертаций;
- курсанты с достижениями и задачами; у двух курсантов есть личный кабинет;
- адъюнкты с планами работы, задачами и достижениями;
- журнал активности демо-пользователей за 30 дней (входы, просмотры, изменения, выгрузки, несколько неудачных входов) — отчёт «Активность пользователей» за последние 7 суток не пуст.

Курсанты и адъюнкты — соавторы части публикаций, докладов и РИД. Задачи есть во всех статусах, часть просрочена, у задач есть обсуждение. Даты привязаны к текущему отчётному периоду, часть записей специально раньше периода, чтобы проверить отбор по периоду.

```bash
uv run python manage.py seed_demo            # если в базе уже есть данные, команда остановится
uv run python manage.py seed_demo --clear    # сначала очистить базу (admin сохранится)
uv run python manage.py seed_demo --seed 42  # другой набор данных; одинаковое зерно — одинаковые данные
```

Если в базе применены не все миграции, `seed_demo` и `clear_data` ничего не меняют и просят сначала выполнить `migrate`.

Если демонстрационная база создана до обновления приложения, в ней нет данных новых разделов. Пересоздайте её:

```bash
uv run python manage.py migrate
uv run python manage.py seed_demo --clear
```

Создаются демо-пользователи, пароль у всех — `demo12345`:

| Логин | Роль | Что посмотреть |
|---|---|---|
| `admin` (создаётся `create_admin`, не `seed_demo`) | суперпользователь | всё, в том числе «Отчёты» → «Активность пользователей» и выгрузка в DOCX |
| `editor` | редактор (группа «Редакторы НИР») | все разделы и сводные показатели, изменение любых записей, все задачи |
| `ivanov` | преподаватель (группа «Преподаватели») | форма 16 со всеми тремя разделами (в том числе РИД) и формы 16 подопечных; кабинет руководителя: свои НИОКР, труды, научная школа (ведущий учёный) с показателями, подопечные курсанты и адъюнкты, «Мои задачи» со счётчиком; остальные разделы закрыты |
| `petrova`, `smirnov` | преподаватели (группа «Преподаватели») | свои кабинеты: свои НИОКР, публикации, РИД, доклады, школы и подопечные; записи `ivanov` им не видны |
| `adjunct1`, `adjunct2` | адъюнкты (группа «Адъюнкты»), руководитель — `ivanov` | кабинет адъюнкта: план работы, свои задачи, достижения и труды, своя научная школа; карточка руководителя закрыта |
| `student1`, `student2` | курсанты с личным кабинетом (группа «Курсанты»), руководитель — `ivanov` | кабинет курсанта: портфолио, свои задачи (у `student1` — во всех статусах), добавление публикации, доклада, достижения; остальные разделы закрыты |

Очистить базу: удалить все предметные данные и всех пользователей, кроме `admin` (в том числе учётные записи преподавателей, адъюнктов и курсантов). Группы и права сохраняются.

```bash
uv run python manage.py clear_data                   # покажет, что будет удалено, и спросит подтверждение
uv run python manage.py clear_data --noinput         # без вопроса
uv run python manage.py clear_data --username boss   # сохранить другого пользователя вместо admin
```

Если сохраняемого пользователя нет в базе, `clear_data` ничего не удаляет.

Развёртывание на сервере описано в [DEPLOY.md](DEPLOY.md).
