Добавь в приложение «Учёт показателей НИР кафедры» раздел «Отчёты». В нём система формирует отчётные документы по данным, которые уже есть в базе. Первый отчёт — «Список научных и учебно-методических трудов» по форме № 16: его смотрят в браузере, печатают и скачивают в формате DOCX.

## Контекст
Проект описан в README.md. Django 5.2, приложения в apps/.
- Труды хранятся в существующих разделах, отдельно их не дублируй:
  - Publication: вид — статья, тезисы, монография, глава, учебник, учебное пособие; выходные данные — source, year, volume, issue, pages, DOI, url, метод imprint; авторы — PublicationAuthor в нужном порядке;
  - IntellectualProperty: вид, номер, даты, правообладатель, авторы;
  - Report: доклады на конференциях, опубликованные тезисы связаны через Report.publication.
- Авторы — наследники AuthorBase (teacher / student / adjunct / external_name). Метод author_lookup(person) даёт фильтр «автор — этот человек».
- Люди с трудами: Teacher, Adjunct, Student. get_person(user) — человек пользователя.
- Личный кабинет — apps/core/cabinet.py: белые списки страниц для ролей (RULES) и проверка «запись своя». Новая страница закрыта для преподавателя, адъюнкта и курсанта, пока её не внесли в списки. Ссылки выводятся через {% record_link %}.
- Оформление — Bootstrap 5, base.html, общие include-шаблоны; есть пример версии для печати (сводная таблица научных школ).

Соблюдай существующую структуру, стиль кода и русский интерфейс.

Перед началом проверь git status: незакоммиченные изменения сначала закоммить отдельным коммитом. Файлы, которые создал не ты (например, test_users.md), не трогай и не коммить.

## Главные принципы
1. Отчёт строится только из существующих данных. Отдельных таблиц «трудов для отчёта» нет. Если для формы не хватает поля, добавь его в существующую модель (см. п. 2) и миграцию.
2. Раздел «Отчёты» — каркас для будущих отчётов. Сделай новое приложение apps/reports с реестром отчётов: описание, кому доступен, ссылка. Форма 16 — первый отчёт в нём. Следующий отчёт должен добавляться без переделки каркаса.
3. Данные отчёта собираются в одном месте — например, функция или класс в apps/reports/form16.py, который возвращает разделы и строки. HTML-страница и DOCX строятся из этого результата, а не собирают данные каждый по-своему.
4. Доступ проверяет существующий механизм прав и кабинета. Не делай отдельной системы прав.

## 1. Форма № 16: содержание
Заголовок:
- «СПИСОК научных и учебно-методических трудов»;
- ФИО человека в родительном падеже, если его можно получить без морфологических библиотек. Иначе используй вариант «Автор: Фамилия Имя Отчество» — выбери и объясни;
- должность и степень (для преподавателя) или категория: «адъюнкт», «курсант, группа …»;
- период, если он задан.

Таблица (столбцы формы 16):
| № п/п | Наименование работы, её вид | Форма работы | Выходные данные | Объём, п. л. или с. | Соавторы |

Разделы (нумерация сквозная):
1. Научные труды: статьи, тезисы докладов, монографии, главы в монографиях.
2. Учебные и учебно-методические издания: учебники и учебные пособия.
3. Объекты интеллектуальной собственности: патенты и свидетельства (РИД).

Пустой раздел выводится с пометкой «нет».

Заполнение столбцов:
- Наименование и вид: «Название (статья)», вид — из Kind.
- Форма работы: «печатная» или «электронная». Добавь в Publication поле «форма работы» с вариантами «печатная» (по умолчанию) и «электронная», миграцию и поле в форме публикации. Для РИД — «электронная» для программ и баз данных, иначе «печатная»; правило вынеси в одно место.
- Выходные данные:
  - для публикаций — imprint плюс DOI, если есть;
  - для РИД — «Свидетельство (патент) № …, дата регистрации …, правообладатель …».
- Объём. Добавь в Publication необязательное поле «объём, п. л.» (десятичное). Если оно заполнено — выводи его. Если нет — число страниц из диапазона pages («15–28» → «14 с.») или текст pages как есть. Для РИД — «—».
- Соавторы: все авторы, кроме самого человека, в порядке авторов, в формате «Иванов С. П.». Внешних соавторов выводи как записаны. Если соавторов нет — «—».

Сортировка внутри раздела — по году, затем по названию. Направление выбери (по возрастанию или убыванию) и объясни.

Доклады: в форму 16 входят опубликованные труды, поэтому доклад попадает в список своими опубликованными тезисами (Report.publication). Доклады без опубликованных тезисов в форму не включаются. Укажи это в пояснении к отчёту на странице.

Подвал:
- строки для подписей: «Автор ____ И. О. Фамилия», «Список верен: заведующий кафедрой ____», «Учёный секретарь ____»;
- дата формирования.

Параметры отчёта (форма на странице):
- человек — выбор только для тех, кому доступен чужой отчёт (см. п. 2);
- период: год с — по (необязательно; по умолчанию все годы);
- разделы для включения (по умолчанию все).

## 2. Доступ
- Отчёт доступен всем, у кого бывают труды: преподавателям, адъюнктам и курсантам с учётной записью.
- Каждый формирует форму 16 на себя.
- Научный руководитель может сформировать её для своих подопечных — курсантов и адъюнктов.
- Редакторы — для любого человека кафедры.
- Чужой отчёт для остальных — 404, как другие чужие записи.
- Добавь страницы раздела в белые списки ролей в apps/core/cabinet.py. Проверка «запись своя» — это сам человек или его подопечный. Используй существующие проверки, не дублируй их.
- Пункт «Отчёты» в шапке:
  - у редакторов и обычных пользователей — рядом с остальными разделами;
  - у преподавателя, адъюнкта и курсанта — рядом с «Мой кабинет».
- В кабинетах (карточках) добавь кнопку «Форма 16». В карточке подопечного руководитель тоже видит эту кнопку.

## 3. Страницы
- /reports/ — список доступных пользователю отчётов: пока один, «Форма 16 — список трудов», с описанием.
- /reports/form16/ — свой отчёт. /reports/form16/<вид человека>/<id>/ — отчёт на конкретного человека. Схему адресов выбери сам: вид человека нужен, потому что pk преподавателя, адъюнкта и курсанта могут совпадать.
- Страница отчёта:
  - форма параметров;
  - таблица в браузере;
  - кнопки «Скачать DOCX» и «Версия для печати»;
  - версия для печати сделана без шапки и кнопок, как у сводной таблицы научных школ.
- Отсутствие запросов в цикле при построении отчёта: авторы загружаются через prefetch.

## 4. DOCX
- Для DOCX добавь зависимость python-docx: закреплённая версия в requirements.txt, обновлённое окружение (uv pip sync). Это единственная новая зависимость. Укажи её в README и DEPLOY.md.
- Документ:
  - A4, книжная ориентация, поля 2 см (левое 3 см);
  - шрифт Times New Roman, 12 пт;
  - заголовок по центру;
  - таблица с границами; строка заголовков повторяется на каждой странице;
  - разумная ширина столбцов («Наименование» и «Выходные данные» — шире);
  - строки разделов на всю ширину таблицы;
  - подписи и дата в конце.
- Ответ:
  - Content-Type для DOCX;
  - имя файла вида «Форма_16_Иванов_С_П.docx». Кириллицу в Content-Disposition передай корректно: filename* с UTF-8 и ASCII-запасной вариант.
- Параметры (период, разделы) в DOCX те же, что на странице.

## 6. Тесты
- Построение отчёта:
  - разделы и отнесение видов к разделам;
  - сквозная нумерация;
  - сортировка;
  - фильтр по периоду и по разделам;
  - соавторы без самого человека и с внешними;
  - объём из п. л., из диапазона страниц и из текста;
  - форма работы;
  - доклад без тезисов не попадает в отчёт, а тезисы доклада попадают.
- Доступ:
  - сам человек каждой роли;
  - руководитель для подопечного;
  - чужой преподаватель — 404;
  - адъюнкт и курсант не видят чужие отчёты;
  - редактор — для любого;
  - преподаватель и адъюнкт с совпадающим pk не путаются.
- Белые списки: страницы отчётов открыты нужным ролям; тест «закрыто по умолчанию» по-прежнему проходит.
- DOCX:
  - ответ 200, правильный Content-Type и имя файла;
  - файл открывается python-docx;
  - в таблице нужные строки;
  - параметры периода применяются.
- Версия для печати.
- Отсутствие запросов в цикле (число запросов не растёт с числом трудов).
- Все существующие тесты проходят.
