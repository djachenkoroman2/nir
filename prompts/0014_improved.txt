Расширь раздел «Отчёты» приложения «Учёт показателей НИР кафедры». Нужно две вещи:
1. У каждой группы пользователей должен быть свой набор отчётов. Каждый отчёт смотрят на странице, печатают и скачивают в DOCX.
2. Карточку пользователя должно быть можно распечатать: скачать в DOCX и открыть версию для печати.

## Контекст
Проект описан в README.md. Django 5.2, приложения в apps/.
- Раздел «Отчёты» — apps/reports:
  - реестр registry.py: ReportType с правилом доступа is_available, список /reports/ показывает только доступные отчёты;
  - форма № 16 (form16.py + docx_export.py) и «Активность пользователей» (activity.py + activity_docx.py). У обоих данные собираются в одном месте, страница и DOCX строятся из одного результата, выгрузка — тот же URL с ?format=docx;
  - общее оформление DOCX — docx_common.py (new_document, add_table, add_row, add_merged_row, set_widths, docx_response);
  - кто может формировать отчёт на человека — access.py (can_view_person_report, report_people).
- Группы и роли:
  - суперпользователь (администратор);
  - «Редакторы НИР» (is_staff) — все данные кафедры;
  - «Преподаватели», «Адъюнкты», «Курсанты» — пользователь с привязанной карточкой Teacher / Adjunct / Student (get_person);
  - пользователь без карточки и без групп — просмотр всех разделов.
- Личный кабинет (apps/core/cabinet.py, RULES) ограничивает преподавателей, адъюнктов и курсантов белыми списками страниц. Новые страницы закрыты для них по умолчанию: нужные внеси в RULES с проверкой «запись своя». Научный руководитель видит карточки и записи своих подопечных. Адъюнкту карточка руководителя закрыта.
- Журнал активности (apps/activity) уже пишет скачивание DOCX как «выгрузка отчёта». Убедись, что новые выгрузки тоже туда попадают.
- Демо-пользователи и пароли — в test_users.md. Его не изменяй и не коммить.

Соблюдай существующую структуру, стиль кода, оформление (Bootstrap 5, base.html) и русский интерфейс.

Перед началом проверь git status: незакоммиченные изменения сначала закоммить отдельным коммитом. Файлы, которые создал не ты (например, test_users.md), не трогай и не коммить.

## Главные принципы
1. Новые таблицы для отчётов не создавай: отчёты строятся из существующих данных.
2. Каждый отчёт — модуль построения данных в apps/reports/ (по образцу form16.py), представление, адрес и запись в REPORTS. Страница, версия для печати и DOCX строятся из одного результата.
3. Доступ определяется существующими механизмами: правило is_available в реестре, access.py, белые списки кабинета. Отдельную систему прав не делай. Чужой отчёт или карточка — 404 (как у формы 16), недоступный тип отчёта — 403.
4. Повторяющееся оформление DOCX (шапка с ФИО и должностью или категорией, период, строки подписей, дата формирования) вынеси в docx_common.py. Форма 16 и отчёт об активности должны выглядеть как раньше: их тесты проходят без изменений.
5. Число SQL-запросов отчёта не зависит от числа записей и людей: используй select_related, prefetch_related и агрегаты.

## 1. Отчёты по группам
Ниже — предлагаемый состав. Если какой-то отчёт не получается построить из имеющихся данных, не выдумывай поля: опиши, чего не хватает, и предложи решение в итоговом отчёте.

Курсант (на себя; руководителю — на подопечных курсантов; редактору — на любого курсанта):
- форма № 16 — уже есть;
- «Отчёт о научной работе курсанта» за период (год с — по или даты): сведения о курсанте (группа, курс, статус, руководитель), публикации, доклады на конференциях, РИД, достижения. Итоги — число работ по видам.

Адъюнкт (на себя; руководителю — на подопечных адъюнктов; редактору — на любого адъюнкта):
- форма № 16 — уже есть;
- «Отчёт о выполнении индивидуального плана» за год обучения или за весь срок: тема диссертации, специальность, курс (apps/adjuncts/study.py), руководитель. Этапы плана по годам: наименование, вид, плановый срок, статус, дата выполнения, отметка руководителя. Итог — сколько этапов выполнено, в работе, просрочено. Строки подписей адъюнкта и научного руководителя;
- «Отчёт о научной работе адъюнкта» за период: публикации, доклады, РИД, достижения, итоги по видам.

Преподаватель (на себя; редактору — на любого преподавателя):
- форма № 16 — уже есть;
- «Отчёт о научной работе преподавателя» за период: публикации, РИД, доклады, участие в НИОКР, научные школы (где он ведущий учёный), защиты подопечных за период;
- «Отчёт о работе с подопечными» за период: по каждому подопечному курсанту и адъюнкту — число трудов и достижений, открытые и просроченные задачи; для адъюнктов — выполнение плана.

Редакторы (все данные кафедры):
- все отчёты выше на любого человека — с выбором человека в форме, как у формы 16;
- «Отчёт о НИР кафедры» — консолидированный и подробный, см. раздел 2.

Администратор (суперпользователь): всё перечисленное и «Активность пользователей» — уже есть.

Пользователь без карточки и не редактор: личных отчётов у него нет, список /reports/ показывает только то, что ему доступно (возможно, пустой список с пояснением).

Общие требования к отчётам:
- в карточке человека (кабинете) — блок или кнопки «Отчёты» со ссылками на отчёты, доступные текущему пользователю на этого человека. Логику вынеси в одну функцию (по образцу form16_url_for);
- список /reports/ сгруппируй по назначению: «Мои отчёты», «Отчёты по подопечным», «Отчёты кафедры», «Администрирование». Показывай только непустые группы;
- параметры отчёта задаются формой на странице (период и т. п.), неверный период — ошибка формы;
- пустой раздел выводится с пометкой «нет»;
- DOCX:
  - A4, Times New Roman 12 пт (в широких таблицах — 10 пт);
  - альбомная ориентация, если столбцов много;
  - строка заголовков таблицы повторяется на каждой странице;
  - ширина столбцов в сумме равна ширине текста;
  - в конце — строки подписей, где они уместны, и дата формирования;
- имя файла — по-русски с ФИО и периодом, плюс ASCII-запасное имя (filename + filename* в UTF-8, через docx_response).

## 2. Общий отчёт по кафедре: консолидированный и подробный
Один отчёт «Отчёт о НИР кафедры» в двух видах. Вид выбирается переключателем на странице:
- консолидированный — агрегированные показатели;
- подробный — перечни записей, из которых эти показатели получены.

Доступ — редакторы и суперпользователь. Остальным — 403. В белые списки кабинета не добавляй.

Параметры (общие для обоих видов):
- период: год с — по или даты с — по. Выбери вариант и объясни. По умолчанию — текущий календарный год;
- разделы для включения (по умолчанию все);
- категории людей: преподаватели, адъюнкты, курсанты (по умолчанию все);
- флажок «Учитывать неработающих, выпущенных и отчисленных» (по умолчанию выключен для таблицы по людям; их труды за период в итоги кафедры входят всегда).

Разделы и показатели:
- Кадровый состав (на дату формирования):
  - преподаватели по должностям, степеням и званиям;
  - адъюнкты по курсам и статусам;
  - курсанты, занимающиеся НИР, по курсам.
- Публикации по видам: статьи, тезисы, монографии, главы, учебники, учебные пособия. Отдельно:
  - индексация: ВАК (по категориям), РИНЦ, ядро РИНЦ, Scopus, Web of Science, квартили;
  - форма работы: печатная или электронная;
  - объём в печатных листах, где он указан;
  - публикации с участием курсантов и адъюнктов.
- РИД по видам.
- Доклады по уровню конференций и форме доклада; число конференций.
- НИОКР: выполнявшиеся в периоде (пересечение сроков с периодом) по статусам, число участников.
- Защиты диссертаций по видам.
- Достижения курсантов и адъюнктов по видам и уровням.
- Научные школы: показатели через существующие расчёты apps/schools/indicators.py (annotate_indicators, indicator_totals). Не дублируй их.

Консолидированный вид:
- таблица «раздел → показатель → значение» с итогами по разделам;
- если период шире одного года — столбцы по годам и столбец «Всего» (динамика);
- таблица «человек × основные показатели»: публикации, из них ВАК / Scopus / WoS, РИД, доклады, НИОКР, достижения. Блоки по категориям людей, итоги по категориям и по кафедре.

Подробный вид — те же разделы, но перечнями записей за период:
- сквозная нумерация внутри раздела;
- полные выходные данные (как в форме 16: imprint, DOI);
- авторы в порядке авторства, сотрудники кафедры отмечены (например, полужирным);
- индексация;
- для докладов — конференция, уровень, даты, докладчики;
- для НИОКР — сроки, статус, руководитель и участники;
- для защит и достижений — все сведения записи;
- в конце каждого раздела — строка «Итого: N», совпадающая с консолидированным видом.

Правила подсчёта (опиши их в пояснении на странице отчёта и в README):
- В итогах кафедры запись считается один раз, сколько бы сотрудников ни было среди её авторов.
- В таблице по людям запись засчитывается каждому автору. Поэтому сумма по людям может быть больше итога кафедры. Покажи это примечанием под таблицей.
- Публикация относится к периоду по году издания, доклад — по дате конференции, РИД — по дате регистрации, защита — по дате защиты, достижение — по дате.
- Записи только с внешними авторами в отчёт кафедры не входят.

Реализация:
- данные строятся в одном месте (apps/reports/department.py);
- консолидированный вид — агрегирующими запросами (Count с filter, группировки по годам). Подробный — выборками с prefetch_related;
- итоги подробного вида должны совпадать с консолидированным: правила отбора записей задай один раз и используй в обоих видах;
- число запросов не зависит от числа записей и людей.

Выгрузка в DOCX — отдельно для каждого вида, с теми же параметрами:
- консолидированный: A4 альбомная (из-за столбцов по годам и таблицы по людям);
- подробный: A4 книжная, разделы — заголовками с нумерацией, перечни — нумерованными абзацами или таблицами (выбери и объясни);
- общее:
  - заголовок «Отчёт о научно-исследовательской работе кафедры» и вид отчёта;
  - период и выбранные разделы и категории;
  - строки подписей «Заведующий кафедрой ____» и «Учёный секретарь ____»;
  - дата формирования;
- имена файлов: «НИР_кафедры_сводный_ГГГГ-ГГГГ.docx» и «НИР_кафедры_подробный_ГГГГ-ГГГГ.docx» и ASCII-запасные имена;
- версия для печати — для обоих видов.

## 3. Печать карточки пользователя
Под «карточкой пользователя» понимается:
- для преподавателя, адъюнкта и курсанта — карточка человека (то, что сейчас показывает его страница / кабинет);
- для редактора, администратора и пользователя без карточки — карточка учётной записи: логин, ФИО, e-mail, группы, роль (категория из отчёта об активности — используй то же определение), дата создания, последний вход, привязанная карточка человека.

Содержимое карточки человека в DOCX:
- Преподаватель: ФИО, должность, учёная степень и звание, контакты, «работает на кафедре», научные школы, НИОКР, подопечные курсанты и адъюнкты, краткая сводка трудов (число по видам).
- Адъюнкт: ФИО, тема диссертации, специальность, год поступления, курс, форма обучения, статус, плановый год защиты, научный руководитель, научная школа, контакты, краткая сводка плана и трудов.
- Курсант: ФИО, учебная группа, курс, статус, научный руководитель, примечание, краткая сводка трудов и достижений.
- Логин учётной записи, если она привязана.

Данные карточки собирай в одном месте (например, apps/reports/cards.py). Страница карточки, версия для печати и DOCX строятся из этого результата.

Кнопки и адреса:
- на странице карточки человека — «Версия для печати» и «Скачать DOCX» (тот же URL с ?format=docx или отдельный адрес — выбери и объясни);
- карточка учётной записи — отдельная страница «Моя учётная запись» (ссылка в меню пользователя) с теми же кнопками.

Кто может печатать:
- свою карточку — любой вошедший пользователь (в том числе курсант и адъюнкт из кабинета);
- карточку подопечного — его научный руководитель;
- карточку любого человека кафедры — редактор;
- карточку чужой учётной записи — только суперпользователь;
- остальным — 404 (или 403 по правилам выше).

Персональные данные (телефон, e-mail) в карточке показывай только тем, кто видит их сейчас на странице карточки. Не расширяй доступ.

## 6. Тесты
- Для каждого нового отчёта:
  - содержимое по разделам и итоги на подготовленных данных;
  - фильтр периода;
  - пустые разделы;
  - DOCX: ответ 200, Content-Type, имя файла, файл открывается python-docx, в таблицах нужные строки;
  - выгрузка записана в журнал как «выгрузка отчёта».
- Доступ по матрице: суперпользователь, редактор, преподаватель (свой / подопечный / чужой), адъюнкт (свой / чужой), курсант (свой / чужой), пользователь без карточки, аноним. Ожидаемые ответы — 200, 403, 404 или переход на вход.
- Список /reports/ и блок «Отчёты» в карточке показывают ровно доступные отчёты.
- Отчёт по кафедре:
  - показатели консолидированного вида на подготовленных данных, в том числе по годам;
  - совместная публикация двух сотрудников считается в итоге кафедры один раз, а в таблице по людям — каждому;
  - записи только с внешними авторами не входят;
  - граничные даты периода;
  - фильтры разделов и категорий;
  - итоги подробного вида совпадают с консолидированным;
  - DOCX обоих видов;
  - доступ: редактор и суперпользователь — 200, остальные — 403, аноним — на вход;
  - число запросов не растёт с объёмом данных.
- Карточки (человека и учётной записи): содержимое, DOCX, доступ по той же матрице. Контакты не показываются тем, кому они сейчас закрыты.
- Белые списки кабинета: новые страницы открыты своим и закрыты чужим.
- Число запросов отчётов не растёт с числом записей (assertNumQueries на двух объёмах данных).
- Тесты формы 16 и отчёта об активности проходят без изменений. Все существующие тесты проходят.

## Чего НЕ делать
- Не создавать таблицы «для отчётов» и не дублировать расчёты, которые уже есть.
- Не собирать данные для DOCX отдельно от страницы.
