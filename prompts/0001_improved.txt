Создай веб-приложение на Django для учёта показателей научно-исследовательской работы (НИР) кафедры вуза.

## Контекст
Это первый этап проекта. Функционал и структура данных по НИР пока не определены, поэтому сейчас нужен только каркас приложения с аутентификацией. Предметные модели (публикации, гранты, конференции и т.п.) НЕ создавай — их добавим позже. Закладывай структуру так, чтобы новые модули было легко добавлять.

## Технические требования
- Python 3.12+, актуальная LTS-версия Django (5.2).
- База данных: SQLite по умолчанию; настройки вынести так, чтобы позже можно было переключиться на PostgreSQL без правки кода (через переменные окружения или файл .env).
- Секретные данные (SECRET_KEY, DEBUG, ALLOWED_HOSTS, параметры БД) — через переменные окружения, с примером в файле .env.example.
- файл .env сгенерируй сразу
- Зависимости зафиксировать в requirements.txt.
- Интерфейс на русском языке, часовой пояс Europe/Moscow.
- Контейнеры (Docker и аналоги) НЕ использовать.

## Пользователи и доступ
- Многопользовательский доступ на основе встроенной системы аутентификации Django (django.contrib.auth).
- Используй собственную модель пользователя (AbstractUser) с самого начала, чтобы позже можно было добавить поля (должность, учёная степень и т.п.) без болезненных миграций.
- Управление пользователями — через стандартную админку Django (/admin/).
- Создай суперпользователя: логин admin, пароль 123. Это учётные данные только для разработки — в документации явно укажи, что их нужно сменить перед вводом в эксплуатацию. Сделай создание администратора воспроизводимым (management-команда или описанная команда в документации), так как стандартные валидаторы паролей Django не пропустят пароль «123» при обычном createsuperuser.

## Страницы
1. Страница входа (/login/): поля «Логин» и «Пароль», кнопка «Войти», сообщение об ошибке при неверных данных.
2. Главная страница (/): доступна только авторизованным пользователям (неавторизованных перенаправлять на страницу входа). Показывает приветствие с именем пользователя, например: «Здравствуйте, <имя>! Добро пожаловать в систему учёта показателей НИР кафедры».
3. Выход из системы: кнопка/ссылка «Выйти» в шапке, после выхода — возврат на страницу входа.
- Общий базовый шаблон (base.html) с шапкой: название системы, имя текущего пользователя, кнопка выхода.
- Простое аккуратное оформление (например, Bootstrap 5), адаптивное для мобильных устройств.

## Документация по развёртыванию
Создай файл DEPLOY.md (на русском) с пошаговой инструкцией:
- системные требования;
- развёртывание для разработки: клонирование, создание виртуального окружения, установка зависимостей, настройка .env, миграции, создание администратора, запуск dev-сервера;
- развёртывание на сервере Linux (Ubuntu) без контейнеров: Gunicorn + systemd-сервис, Nginx как обратный прокси, сбор статики (collectstatic), настройки безопасности (DEBUG=False, ALLOWED_HOSTS, смена пароля admin), опционально HTTPS;
- переход на PostgreSQL;
- обновление приложения и резервное копирование базы данных.
Также добавь краткий README.md: назначение проекта, быстрый старт, структура проекта.

## Чего НЕ делать
- Не придумывать предметные таблицы и функционал НИР.
- Не добавлять регистрацию пользователей через сайт — пользователей заводит администратор.
- Не использовать Docker.

## Результат
- Рабочий проект, который запускается командами из README.
- После выполнения кратко перечисли созданные файлы и команды для запуска, и проверь, что миграции применяются и вход под admin/123 работает.
