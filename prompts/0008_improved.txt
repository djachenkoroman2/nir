Доработай раздел «Курсанты» приложения «Учёт показателей НИР кафедры»: научный руководитель курсанта должен ставить курсанту задачи и вести по ним заметки — так же, как это сделано для адъюнктов в разделе «Адъюнктура».

## Контекст
Проект описан в README.md. Django 5.2, приложения в apps/.
- apps/students: Student (научный руководитель — supervisor, Teacher, необязателен; права руководителя через is_supervised_by), StudentAchievement. У курсантов нет учётных записей.
- apps/adjuncts: Adjunct, PlanStage, Task, TaskComment и менеджер задач:
  - доступ к задачам — в apps/adjuncts/access.py (can_view_tasks, can_manage_tasks, visible_tasks, allowed_transitions, attention_count, has_task_menu);
  - страницы задач — в task_urls.py (пространство имён tasks, /tasks/): «Мои задачи», страница задачи с лентой комментариев, смена статуса, удаление комментария;
  - Task.set_status заполняет дату завершения и пишет служебный комментарий «Смена статуса: X → Y»;
  - счётчик «Мои задачи» в шапке — context processor apps.adjuncts.context_processors.task_menu.
- Права — apps/core/permissions.py и тег {% can %}. Демо-данные — seed_demo, очистка — clear_data и DOMAIN_MODELS в _base.py.

Соблюдай существующую структуру, стиль кода, оформление (Bootstrap 5, base.html, общие include-шаблоны) и русский интерфейс.

Перед началом проверь git status: незакоммиченные изменения сначала закоммить отдельным коммитом.

## Главные принципы
1. Один менеджер задач, а не два. Не создавай отдельные модели StudentTask и StudentTaskComment и не копируй представления и шаблоны. Обобщи существующую модель Task: исполнитель — адъюнкт или курсант. Список «Мои задачи», страница задачи, комментарии, смена статуса и счётчик работают для обоих видов.
2. Модели остаются в apps/adjuncts. Перенос таблиц в другое приложение не нужен. Если общий код задач заметно разрастётся, его можно вынести в отдельный модуль внутри apps/adjuncts.
3. У курсанта нет учётной записи, поэтому он в системе не работает. Задачи курсанта ведут его научный руководитель и редакторы: создают, меняют статус, пишут комментарии (заметки о ходе работы). Учётные записи курсантам в этом промпте не добавляй.
4. Поведение задач адъюнктов не должно измениться. Все существующие тесты должны проходить без правок, кроме счётчиков запросов, если они изменились по уважительной причине (объясни её).

## 1. Модель
- В Task добавь необязательный FK student (Student, CASCADE, related_name='tasks'). Поле adjunct тоже сделай необязательным.
- CheckConstraint: заполнено ровно одно из полей adjunct и student. Добавь проверку и в clean().
- Этап плана (plan_stage) допустим только у задачи адъюнкта, и только этап этого же адъюнкта. У задачи курсанта план не предлагается.
- Добавь свойство исполнителя (например, task.person), которое возвращает адъюнкта или курсанта. Через него работают ссылки, права (is_supervised_by) и вывод «кому поставлена задача». Посмотри, где сейчас используется task.adjunct напрямую (шаблоны, access.py, views, админка, seed_demo), и переведи эти места на общий вариант там, где это нужно.
- Статусы для задач курсанта: «новая», «в работе», «выполнена», «отменена». «На проверке» курсанту не предлагается: проверять некому, кроме самого руководителя. Набор статусов задаётся в одном месте, без условий по всему коду.
- Миграция данных не нужна: существующие задачи уже принадлежат адъюнктам.

## 2. Права
- Задачи курсанта видят только его научный руководитель и редакторы. Для всех остальных, включая адъюнктов и других преподавателей, страницы задачи возвращают 404, а блок задач в карточке курсанта и столбец в списке не показываются.
- Руководитель и редакторы создают, изменяют, удаляют задачи курсанта, переводят их в любой допустимый статус и комментируют.
- Если у курсанта нет руководителя, его задачи ведут только редакторы.
- Если у курсанта сменили руководителя, задачи остаются за курсантом и видны новому руководителю.
- Удаление курсанта удаляет и его задачи с комментариями.
- Права выдай миграцией группе «Преподаватели» только при необходимости. Модель Task уже существует, поэтому скорее всего новых прав не понадобится. Права адъюнктов не расширяй.

## 3. Интерфейс
- Карточка курсанта: раздел «Задачи» (только для тех, кому видны) — открытые задачи со сроком и статусом, ссылки «Все задачи» и «Поставить задачу».
- /students/<id>/tasks/ — задачи курсанта с фильтром по статусу, как /adjuncts/<id>/tasks/.
- /students/<id>/tasks/add/ — новая задача. Форма та же, что у адъюнкта, но без этапа плана.
- Список курсантов: столбец «Открытые задачи» (только для тех, кому видны задачи), без запросов в цикле.
- «Мои задачи» (/tasks/) для преподавателя: задачи его адъюнктов и курсантов. Добавь фильтр «Исполнитель» (адъюнкты / курсанты / все) рядом с фильтрами по человеку и статусу. В столбце исполнителя выводи ФИО со ссылкой и пометкой «курсант» или «адъюнкт».
- Для редактора «Мои задачи» показывает задачи, которые видны ему как руководителю, — сохрани текущую логику.
- Страница задачи: в заголовке и хлебных крошках — исполнитель со ссылкой на его карточку (адъюнктура или курсанты).
- Карточка преподавателя: в блок «Научное руководство курсантами» добавь число открытых задач у каждого курсанта.
- Счётчик в шапке для руководителя: задачи «на проверке» у адъюнктов (как сейчас) плюс просроченные открытые задачи курсантов. Подпиши значение в title бейджа, чтобы было понятно, что считается. Пункт «Мои задачи» показывается преподавателю, у которого есть адъюнкты или курсанты.
- Админка Task: фильтр по виду исполнителя, поиск по ФИО курсанта.

## 4. Демо-данные
- seed_demo: 2–4 задачи для нескольких обучающихся курсантов, в том числе у курсантов ivanov. Нужны разные статусы, просроченные задачи и комментарии руководителя.
- Порядок в DOMAIN_MODELS проверь: Task и TaskComment должны удаляться раньше Student.
- seed_demo проверяй только на копии базы.

## 5. Тесты
- Ограничение: у задачи заполнен ровно один исполнитель; этап плана у задачи курсанта запрещён.
- Видимость задач курсанта: руководитель, редактор, чужой преподаватель (404), адъюнкт (404), курсант без руководителя (только редактор).
- Переходы статусов для задачи курсанта: «на проверке» недоступно, служебная запись в ленте, дата завершения.
- «Мои задачи» руководителя показывает задачи адъюнктов и курсантов, фильтр «Исполнитель» работает.
- Счётчик в шапке учитывает просроченные задачи курсантов.
- Удаление курсанта удаляет задачи.
- Отсутствие запросов в цикле: список курсантов и «Мои задачи» со смешанными задачами (assertNumQueries).
- seed_demo создаёт задачи курсантов.
- Все существующие тесты проходят.
